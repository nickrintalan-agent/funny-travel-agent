# Agent Spec: funny-travel-agent

## Overview
`funny-travel-agent` ("Captain Layover & The JetLag Jesters") is a helpful, witty, and comedic multi-agent travel concierge built with the Google Agent Development Kit (ADK) in Python. It helps travelers search flights and hotels, look up destination advisories and hidden gems from a persistent knowledge base, craft multi-day itineraries, and book reservations with human-in-the-loop (HITL) confirmation—all while delivering punchy travel humor and adhering strictly to the 19-point **AgentOps Code Review Matrix** (95 points total).

It includes both a custom, interactive Travel Agency Web UI served via FastAPI (`app/fast_api_app.py` + `app/static/index.html`) and full compatibility with `agents-cli playground` / ADK Web and A2A protocol.

## Language
`python` (ADK Python)

## Architecture & Sub-Agents
To satisfy **Multi-Agent Patterns** and **Strategic Model Routing** while keeping the scope right-sized:
1. **`travel_concierge_coordinator` (`LlmAgent`, Root Agent)**:
   - Persona: "Captain Layover", a seasoned, hilarious, yet fiercely competent travel concierge.
   - Responsibilities: Greets the user, recalls cross-session traveler preferences, handles general travel banter, applies dynamic model routing (`before_model_callback` selecting Flash for simple turns and Pro for complex multi-constraint requests), and delegates specialized tasks to sub-agents.
2. **`travel_search_specialist` (`LlmAgent`, Fast Model — Gemini Flash)**:
   - Responsibilities: High-speed tool execution for searching commercial flights, searching hotel accommodations, and retrieving destination travel advisories / cultural tips from the persistent knowledge store.
3. **`itinerary_booking_pipeline` (`SequentialAgent` & `LlmAgent`, Reasoning Model — Gemini Pro)**:
   - Composed of:
     - `itinerary_architect_agent` (Gemini Pro): Synthesizes search results, budget math, and traveler preferences into a structured day-by-day comedic itinerary.
     - `reservation_booking_agent` (Gemini Pro): Handles high-stakes reservation actions (`book_confirmed_flight_reservation`, `book_confirmed_hotel_reservation`) protected by an explicit **Human-in-the-Loop (HITL)** confirmation hook (`ToolContext.request_confirmation` / explicit confirmation token verification).

## Example Use Cases
1. **Flight & Hotel Discovery with Humor**
   - **Input:** `"Find me flights from SFO to Tokyo (NRT) departing 2026-11-10 for 2 passengers in economy, and a boutique hotel in Shinjuku under $250/night."`
   - **Expected Output:** Coordinator delegates to `travel_search_specialist` (Flash), invokes `search_commercial_flights_by_route` and `search_hotel_accommodations_by_city`, and returns structured flight/hotel options with witty commentary on middle seats and jet lag.
2. **Multi-Day Itinerary Planning & Destination Advisory Lookup**
   - **Input:** `"Plan a 3-day foodie and anime itinerary in Tokyo and check if there are any travel advisories or etiquette rules I shouldn't mess up."`
   - **Expected Output:** Retrieves advisories/etiquette via `retrieve_destination_travel_advisory` (backed by Vertex AI Search / persistent vector & SQLite knowledge store), then runs the Pro itinerary planner to produce a 3-day plan with budget breakdown and jokes.
3. **High-Stakes Booking with Human-in-the-Loop (HITL) Confirmation**
   - **Input:** `"Book flight JL-001 for Alex Rivera (email: alex.rivera@example.com, passport: P12345678) for $820."`
   - **Expected Output:**
     - PII (`alex.rivera@example.com`, `P12345678`) is actively redacted in logs and memory via the PII scrubber (Cloud DLP API + regex fallback).
     - `book_confirmed_flight_reservation` triggers the **Human-in-the-Loop Hook** (`confirmed=False` or `tool_context.request_confirmation`), pausing execution and asking the user for explicit confirmation of the flight number, total price, and non-refundable policy before finalizing.
     - Once the user explicitly confirms (`confirmed=True`), the booking confirmation code is issued and saved asynchronously to persistent memory.
4. **Guided Error Recovery**
   - **Input:** `"Find flights from Atlantis (ATL-999) to Narnia on 1999-01-01."`
   - **Expected Output:** Tool returns a structured `ToolResponse` error with explicit `recovery_instructions` (valid 3-letter IATA airport codes and future ISO-8601 dates), and the agent gracefully guides the user to provide valid airports and dates without crashing.

## Tools Required
All tools reside in `app/tools.py` and satisfy **Category 1 (Tool & Interface Design)**:
- **Comprehensive Tool Docstrings**: Every tool includes detailed docstrings with purpose, args, returns, and error recovery behavior.
- **Descriptive Naming**: Highly specific verb-noun tool names (`search_commercial_flights_by_route`, `search_hotel_accommodations_by_city`, `retrieve_destination_travel_advisory`, `calculate_trip_budget_estimate`, `book_confirmed_flight_reservation`, `book_confirmed_hotel_reservation`, `save_traveler_preference_to_memory`).
- **Explicit JSON Schemas**: All tools use strict Pydantic `BaseModel` input and output schemas (`FlightSearchInput`, `FlightSearchOutput`, `HotelSearchInput`, `HotelSearchOutput`, `DestinationAdvisoryInput`, `DestinationAdvisoryOutput`, `BookingReservationInput`, `BookingReservationOutput`) with `Field(..., description=..., pattern=..., ge=..., le=...)` constraints and `model_validate` enforcement.
- **Guided Error Handling**: Tools catch validation and domain errors and return structured error payloads containing `status="error"`, `error_code`, `message`, and actionable `recovery_instructions` for the LLM.

## Data Flow, Context & Memory (Category 2)
1. **Robust System Instructions**: Defined in `app/prompts.py` as a clear "Agent Constitution" specifying persona ("Captain Layover"), comedic rules (warm, witty, never mean or offensive), domain knowledge (aviation/hospitality), tool usage protocol, and safety boundaries.
2. **History Compaction**: Configured via ADK's `EventsCompactionConfig` (sliding window `compaction_interval` & `overlap_size` on `App`) and `ContextCacheConfig`, plus a token/sliding-window truncation callback (`before_model_callback`) that summarizes/trims older turns when context exceeds threshold.
3. **Persistent Session State & Knowledge Store**:
   - Supports Google Cloud `VertexAiSessionService` / `VertexAiMemoryBankService` (and Vertex AI Search datastore when configured via env vars) plus a built-in persistent SQLite + vector similarity store (`app/memory.py`) so persistent session history, user preferences, and destination RAG advisories work both in Cloud Run and local assessment environments.
   - Includes `PreloadMemoryTool` / automatic memory recall on session start.
4. **Async Memory Operations**: Expensive memory extraction, summarization, and consolidation run asynchronously via `asyncio.create_task` in `after_agent_callback` / background workers (`async_consolidate_traveler_memory`) so the UI response never blocks.

## Constraints, Guardrails & Safety Rules (Category 3)
1. **Guardrails & Policy Plugins**:
   - Implemented as an ADK `BasePlugin` (`TravelSafetyAndPolicyPlugin` in `app/guardrails.py`) registered on the `App` / `Runner`, plus `before_model_callback`, `after_model_callback`, and `before_tool_callback`.
   - Integrates Google Cloud Model Armor / perspective safety checks (with deterministic policy + LLM self-evaluation fallback) to block prompt injection, unsafe/illegal travel requests (e.g., smuggling, restricted travel violations), off-topic non-travel abuse, and unverified price fabrication.
2. **Human-in-the-Loop (HITL) Hooks**:
   - High-stakes booking tools (`book_confirmed_flight_reservation`, `book_confirmed_hotel_reservation`) enforce both ADK's `tool_context.request_confirmation` and an explicit `user_confirmed: bool` + confirmation token gate in `before_tool_callback`. Any attempt to execute a booking without explicit human confirmation halts and returns a `PENDING_HUMAN_CONFIRMATION` state requiring user sign-off.

## Observability, Tracing & PII Redaction (Category 4)
Implemented in `app/observability.py`:
1. **Structured JSON Logging**: Uses `python-json-logger` and `google-cloud-logging` (`StructuredLogHandler`) to emit structured JSON log records with `timestamp`, `severity`, `agent_name`, `session_id`, `trace_id`, `span_id`, and `event_type` (zero `print()` statements in production code).
2. **Intent vs. Outcome Capture**: Explicit `before_agent_callback`, `after_agent_callback`, `before_tool_callback`, and `after_tool_callback` hooks log a paired `INTENT` record (intended tool/agent, sanitized arguments, rationale) before execution and an `OUTCOME` record (status, latency_ms, sanitized result summary) after execution.
3. **Distributed Tracing**: Uses OpenTelemetry (`opentelemetry-api`, `opentelemetry-sdk`, `CloudTraceSpanExporter`) to create linked parent/child spans (`travel_agent.request` -> `agent.<name>` -> `tool.<name>`) propagating trace context from query to final answer.
4. **PII Redaction**: Active scrubbing pipeline (`PIIRedactor`) invoked before every log emission and before every memory write. Uses Google Cloud DLP API (`google.cloud.dlp_v2`) when available in GCP with an always-on deterministic regex scrubbing layer for emails, phone numbers, credit card numbers, passport numbers, and SSNs.

## Infrastructure, CI/CD & Secret Management (Category 5)
1. **Automated Evaluation Suites**:
   - Golden dataset in `tests/eval/datasets/` and rubric configuration in `tests/eval/eval_config.yaml` compatible with `agents-cli eval run`, plus deterministic unit tests in `tests/unit/` testing schemas, guided error recovery, PII redaction, HITL blocking, compaction, and secret loading.
2. **Infrastructure as Code (IaC)**:
   - Terraform configurations in `infra/terraform/` (Cloud Run service, IAM service accounts, Secret Manager secrets, Cloud Trace/Logging/DLP API enablement, Artifact Registry) and GitHub Actions CI/CD workflows in `.github/workflows/`, scaffolded and managed with `agents-cli`.
3. **Secure Secret Management**:
   - `app/secrets.py` retrieves API keys and credentials dynamically from Google Cloud Secret Manager (`google.cloud.secretmanager.SecretManagerServiceClient`) with environment variable injection fallback—zero hardcoded API keys or credentials anywhere in the repo.

## Assumptions
- **Self-contained + GCP Hybrid Mode**: Because the automated grading agent clones the GitHub repository and inspects/runs it, all Google Cloud integrations (Secret Manager, Cloud DLP, Cloud Logging, Cloud Trace, Vertex AI Session/Memory Bank) include real GCP SDK implementations with automatic local fallbacks (SQLite persistent store, regex PII redaction, structured stdout JSON logger, in-memory OTel span exporter) so the app never crashes if a grader environment lacks a specific GCP API permission.
- **Models**: Uses `gemini-2.5-flash` (or latest available Flash model in the project's Vertex AI region) for fast search/lookup tasks and `gemini-2.5-pro` (or latest available Pro model) for complex itinerary planning and booking coordination.
